# 文章已读/未读状态设计

## 目标

为每篇归属用户的文章提供持久化已读/未读状态：打开详情自动已读，并可重新标记未读。

## 设计

- 使用 `articles.read_at` 可空时间字段，空值表示未读。
- 使用显式 `PUT/DELETE /api/articles/{id}/read` 修改状态，详情 `GET` 保持只读。
- Service 复用文章归属校验，禁止跨用户状态修改。
- 看板与收藏页显示状态，打开详情后同步为已读，详情中可标记未读。
- 本期不实现筛选、统计、批量操作或阅读历史。

## 验收

- 新文章默认未读。
- 状态持久化并在看板、收藏页和详情中一致。
- 跨用户操作返回资源不存在语义。
- 后端测试、前端构建、审核和接口/UI 验证通过。
