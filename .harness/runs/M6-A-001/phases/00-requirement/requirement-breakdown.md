# M6-A-001 需求拆解

## 来源需求

为 FrontierScan 增加文章已读/未读状态，并按照默认单业务工作流完成业务开发闭环。

## 已确认业务语义

- 新采集文章默认未读。
- 用户成功打开文章详情后自动标记为已读。
- 用户可以在文章详情中重新标记为未读。
- 阅读状态属于文章归属用户，任何状态修改都必须校验 `userId`。

## 假设

- 当前 `articles` 已按 `user_id` 归属单一用户，阅读状态可直接存储在文章表。
- 本期不增加“仅看未读”筛选、批量已读或未读统计，避免扩大范围。
- 自动标记已读通过显式写接口完成，`GET /api/articles/{id}` 保持只读。

## 影响范围

| 区域 | 影响 |
| --- | --- |
| 数据库 | 新增 `articles.read_at` 可空时间字段 |
| 后端 | Article 实体、Service 状态变更、Controller 接口、权限测试 |
| 前端 | Article/FavoriteArticle 类型、API 封装、看板与收藏页状态展示和交互 |
| Harness | M6-A-001 单 Story 状态、阶段产物和验证报告 |

## 验收标准

1. 新文章和历史文章在 `read_at` 为空时表现为未读。
2. 当前用户打开文章详情后，前端调用写接口并将文章持久化为已读。
3. 已读文章在看板和收藏页显示明确的已读状态，未读文章显示明确的未读状态。
4. 用户可在详情抽屉中将已读文章重新标记为未读，列表与详情状态同步。
5. 其他用户不能修改不属于自己的文章阅读状态，对外保持资源不存在语义。
6. 后端针对性测试、后端完整测试、前端构建、代码审核和可用环境下的接口/UI 验证通过。

## 非目标

- 未读筛选、未读数量统计。
- 批量标记已读或未读。
- 阅读历史、阅读次数、阅读进度。
- Git 提交、推送、PR、发布或部署。

## 知识与风险

- `llm-knowledge` freshness 检查结果为 backend/frontend/common 全部 fresh。
- `GET` 写副作用会破坏接口语义，因此使用显式状态接口。
- 数据库迁移是全局变更，使用现有最新迁移之后的 `V11`。
