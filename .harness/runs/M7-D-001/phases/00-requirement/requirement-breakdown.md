# M7-D-001 需求拆解

## 原始需求

在 Dashboard 文章列表中增加“全部、未读、已读”筛选，用于快速区分尚未阅读和已经阅读的文章。

## 范围

- Dashboard 文章列表增加三个互斥的阅读状态选项。
- 后端文章列表接口支持 `readStatus=all|unread|read`。
- 阅读状态筛选可与现有分类、网站、关键词、标签、日期和分页条件组合。
- 非法 `readStatus` 返回明确的客户端错误。
- 所有查询继续按当前认证用户隔离数据。

## 非目标

- 不修改 Favorites 页面的筛选行为。
- 不增加未读数量统计。
- 不增加批量标记已读或未读。
- 不持久化用户上次选择的筛选状态。
- 不增加数据库字段或迁移。

## 验收标准

### AC-READ-FILTER-1

在 Dashboard 选择“未读”时，只返回并展示当前用户 `readAt=null` 的文章。

### AC-READ-FILTER-2

在 Dashboard 选择“已读”时，只返回并展示当前用户 `readAt!=null` 的文章。

### AC-READ-FILTER-3

选择“全部”或未提供参数时保持现有文章列表语义，并能与已有分类、网站、关键词、标签、日期和分页条件组合。

### AC-READ-FILTER-4

非法阅读状态参数被明确拒绝，阅读状态筛选不会返回其他用户文章。

### AC-READ-FILTER-5

切换阅读状态后回到第一页，界面选中状态、请求参数和文章结果保持一致。

## 开放问题

无。

## 风险

- 原生查询的主查询和 `countQuery` 必须同时增加阅读状态条件，否则分页总数会错误。
- 前端没有组件测试框架，界面行为需要通过真实浏览器验证，不能仅以构建成功代替。
